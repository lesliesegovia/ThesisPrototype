# Technical Constraints for NewsCardPlus Design

Based on the current codebase, here are the key technical constraints you should consider:

## 1. **Existing Theme System Structure**

- **Typography**: `.categoryLabel`, `.cardHeadline`, `.cardBody`
- **Colors**: `.accentPrimary`, `.accentSecondary`, `.textPrimary`, `.backgroundPrimary`, `.backgroundScreen`
- **Spacing**: `.card`, `.cardContent`

**Design Constraint**: Any new text styles, colors, or spacing values in NewsCardPlus should either use these existing tokens or you'll need to request new ones be added to the theme system.

## 2. **Image Resource System**

Current cards use typed image resources (`.featured`, `.compact`) rather than dynamic URLs or asset names.

**Design Constraint**: If NewsCardPlus needs different image dimensions or aspect ratios, a new ImageResource (e.g., `.plus`) will need to be defined. The images are rendered with `.resizable()` and `.scaledToFit()`, so aspect ratios matter.

## 3. **Card Layout Patterns**

Two established patterns exist:
- **Featured**: Vertical stack (image top, content below)
- **Compact**: Horizontal layout with fixed height (100pt)

**Design Constraint**: NewsCardPlus should follow a clear, consistent pattern. Mixing patterns or creating complex nested layouts may require additional development time.

## 4. **Text Truncation Behavior**

Current implementation uses `.lineLimit()`:
- Headlines: 2 lines max
- Descriptions: 2-3 lines max

**Design Constraint**: If NewsCardPlus needs different truncation behavior or dynamic height based on content, this needs to be explicitly specified as it deviates from the current pattern.

## 5. **Corner Radius Standards**

- Card containers: 12pt radius
- Internal images (compact): 8pt radius

**Design Constraint**: Maintain these radius values for consistency unless there's a strong reason to deviate.

## 6. **Data Model Limitation**

The `NewsArticle` model includes:
- `category`, `headline`, `description`, `cardType`

**Design Constraint**: If NewsCardPlus requires additional data fields (author, timestamp, tags, read time, etc.), the data model will need to be extended, which impacts the entire data pipeline.

## 7. **Padding Consistency**

All cards use 16pt internal padding.

**Design Constraint**: Maintain this unless NewsCardPlus has a specific reason for different spacing.

## Recommendations for Your Design Handoff:

✅ **Annotate** any new spacing values needed  
✅ **Specify** which existing typography styles to use (or define new ones)  
✅ **Define** the image aspect ratio and dimensions

struct ContentView: View {

## Edge Cases Not Fully Accounted For:

### 1. **Long Text Handling**
The current `CategoryPill` implementation does **not** have any text truncation or line limits:
```swift
Text(title)
    .font(AppTheme.Typography.categoryLabel)
    // No .lineLimit() or .truncationMode() specified
```

**Potential issues:**
- Very long category names could break the pill's visual design
- Text might wrap to multiple lines, distorting the capsule shape
- Horizontal scrolling in `CategoryFilterBar` might not work as expected with variable-width pills

**Recommendation:** Add `.lineLimit(1)` and `.truncationMode(.tail)` to prevent wrapping.

### 2. **Minimum Touch Target Size**
The padding is fixed at:
```swift
.padding(.horizontal, 16)
.padding(.vertical, 8)
```

For very short category names (e.g., "AI"), the touch target might be smaller than the recommended 44x44 points for iOS accessibility guidelines.

### 3. **State Transitions/Animations**
There's no animation for the state change between selected/unselected:
- Color changes happen instantly
- No smooth transition for better UX

**Recommendation:** Add animation:
```swift
.animation(.easeInOut(duration: 0.2), value: isSelected)
```

### 4. **Disabled State**
The Figma design may include a disabled state, but the codebase only handles `isSelected` (Boolean), with no provision for:
- Disabled/inactive pills
- Loading states
- Error states

### 5. **Dynamic Type Support**
No explicit handling for users who increase font sizes via accessibility settings, which could cause layout issues with the fixed padding.

These edge cases should be addressed to ensure the implementation matches design intent across all use cases.
